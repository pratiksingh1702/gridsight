# GridSight: Project Analysis & Architecture Walkthrough

This document provides a deep-dive analysis of the **GridSight** prototype, comparing the current implementation against the original 4-week plan and specifying the path toward real-world deployment for BESCOM.

## 1. Project Overview
**GridSight** is an AI-powered decision-support system designed to solve two critical problems for electricity distribution companies (DISCOMs) like BESCOM:
1.  **Demand Forecasting & Risk Zoning**: Predicting localized load spikes to prevent transformer failures.
2.  **Theft & Anomaly Detection**: Identifying revenue leakage (bypass, tampering) via a context-aware probabilistic fusion engine.

---

## 2. Architectural Layers

The project follows a classic three-tier architecture, currently optimized for a local "Hackathon Prototype" environment.

### A. Data Layer (The Foundation)
*   **Current State**: 100% Synthetic data generated by `generate_data.py`.
*   **Physics Realism**: High. Includes sinusoidal daily loads (peaks at 6-8 PM), weekly seasonality (weekdays vs weekends), and temperature sensitivity (load increases > 35°C).
*   **Validation**: `validate_and_load.py` implements a robust pipeline to check for negative kWh, future timestamps, and data gaps.
*   **Storage**: Defaults to CSV (`USE_DB = False` in `config.py`) for portability, but `setup_db.py` contains the full schema for a **TimescaleDB** (PostgreSQL) implementation.

### B. Compute Layer (The Intelligence)
*   **Demand Engine**: 
    *   **Per-Meter**: Uses **Facebook Prophet** (`forecast_meters.py`) with a Bangalore-specific holiday calendar.
    *   **Zone-Level**: Currently a "Lite" simulation in `forecast_zone.py`. The plan calls for a Temporal Fusion Transformer (TFT), but the code uses a noise-injected mean for CPU compatibility.
    *   **Anomaly Engine (The 6-Agent Ensemble)**:
    1.  **CUSUM Agent**: Detects sudden downward breaks in consumption.
    2.  **Peer Agent (KNN)**: Compares a meter to its 20 "social twins" (similar usage profile).
    3.  **Rules Agent**: Checks physics "impossibilities" (e.g., zero consumption in occupied homes, voltage dips during theft).
    4.  **Pattern Agent**: Scans for "signatures" like perfectly flat lines or night-only bypass.
    5.  **Feeder Balance Agent**: Correlates consumer totals with feeder-head SCADA data.
    6.  **Isolation Forest Agent**: An unsupervised model that catches multivariate outliers.
    *   **Residual Intelligence**: Forecast vs actual residuals labeled as sudden drop, periodic zero, or gradual drift.
    *   **Context + Temporal Intelligence**: Time-of-day, load regime, feeder type, and persistence trend features.
    *   **Adaptive Fusion**: Probabilistic fusion with physics confidence calibration and agent reliability.
    *   **Risk-Adjusted Economics**: Expected value drives priority and scheduling.

### C. Output Layer (The Interface)
*   **Unified Dashboard**: `app.py` provides a high-end Streamlit interface with tabs for Forecasting and Theft.
*   **Decision Support**: `generate_case_file.py` creates PDF Inspection Case Files with evidence tables and field checklists.
*   **Mobile View**: `field_app.py` is optimized for field inspectors to log outcomes.

## 4. Current Issues & Bypasses

1.  **TFT Simulation**: The zone-level forecast does not use actual PyTorch models. It uses `np.random.normal` to generate the P10/P90 bands.
2.  **Database Sync**: If `USE_DB` is toggled, several files (agents) still default to reading from `data/processed/`.
3.  **Feedback Coverage**: The learning loop expects inspection outcomes; production pilots should automate this feed from field tools.

## 5. Path to "Real-World" Integration

To move this from a hackathon prototype to a BESCOM-ready pilot:

### 1. Integration of Real Data
*   **MDMS Connector**: Replace `data/meter_readings/` with an API connector to BESCOM's Meter Data Management System.
*   **Weather API**: Integrate **Open-Meteo** or **IMD** live feeds into `forecast_meters.py`.

### 2. Infrastructure Scaling
*   **Enable TimescaleDB**: Set `USE_DB = True` and update the data pipeline to perform SQL `INSERT` instead of `.to_csv`.
*   **Batch Processing**: Run the Fusion Engine as a nightly cron job rather than on-demand in the UI.

### 3. Model Refinement
*   **Train TFT**: Use a GPU instance to train the actual `pytorch-forecasting` model for the 5 feeders to replace the simulation.
*   **Feedback Loop**: Implement the weight update logic in `update_weights.py` to automatically tune agent importance based on field inspection outcomes.

### 4. Security & Privacy
*   **Anonymization**: Ensure PII (names, addresses) are stored in a separate, encrypted table, with the Compute Layer only seeing `meter_id` and `kwh`.

## 6. How it Works (Data Flow)
1.  **Ingest**: Raw data lands in `data/meter_readings`.
2.  **Clean**: `validate_and_load.py` fills gaps and moves data to `data/processed`.
3.  **Detect**: `fusion_engine.py` triggers all agents, residual intelligence, physics confidence, context, and temporal features.
4.  **Fuse**: Adaptive probabilistic fusion computes $P(\text{theft})$ with confidence intervals.
5.  **Decide**: Expected value prioritization and hierarchical classification drive actioning.
6.  **Visualize**: `app.py` displays the map (demand) and the prioritized action table.
7.  **Act**: Field supervisor downloads a PDF and logs inspection outcomes for learning.

## 7. UI/UX Walkthrough (For Non-Technical Users)

The GridSight interface is designed to be used by BESCOM operational supervisors. It translates complex ML outputs into simple "Health" signals.

### A. Demand & Risk Map
*   **The Map**: Shows distribution transformers across Bangalore. 
    *   🟢 **Green**: Safe. Electricity load is within normal limits.
    *   🔴 **Red**: Critical. The AI predicts the transformer will exceed 95% capacity within 24 hours.
*   **The Forecast Chart**: Shows three lines. The **Expected Load** (Middle) and the **Best/Worst Case** (Bands). If the Worst Case (P90) touches the top of the chart, it's time to act.
*   **Recommendations**: Plain-language advice (e.g., "Transfer 15% load") so supervisors don't need to be engineers to make decisions.

### B. Anomaly Detective
*   **The Detectives (Agents)**: We use 6 different "Digital Detectives" to check for theft. 
    *   *Example*: The **"Signature Matcher"** looks for patterns like bypass wiring, while the **"Grid Auditor"** checks if the energy leaving the substation matches the energy billed to houses.
*   **P(Theft)**: A calibrated probability with a confidence interval.
*   **Expected Value**: Prioritizes cases where probable loss justifies inspection.
*   **PDF Case File**: Clicking this generates an official document with reasoning chain and checklist.

### C. Demo Simulation
*   Located in the sidebar, this mode demonstrates the system's "Intelligence" by walking through a **Vacation Scenario**. It shows how the AI correctly identifies a family on holiday (zero usage) without falsely accusing them of theft.

## 8. Operational Playbook (Step-by-Step Commands)

Follow these commands in sequence to run, test, and analyze the entire project.

### Step 1: Initialize the Environment
Generate the 200-meter synthetic dataset and run the validation pipeline to clean the data.
```powershell
python generate_data.py
python validate_and_load.py
```

### Step 2: Set Up the Database (Optional)
If you wish to use TimescaleDB instead of CSVs, ensure Postgres is running and execute:
```powershell
python setup_db.py
```
*Note: Update `config.py` with `USE_DB = True` after this.*

### Step 3: Train Forecast Models
Train the Prophet models for individual meters (takes ~1-2 mins for 200 meters).
```powershell
python forecast_meters.py
```

### Step 4: Run the Anomaly Engine
Run the fusion engine for a sample of meters to populate the escalation logs.
```powershell
python fusion_engine.py
```

### Step 5: Launch the Dashboard
Open the interactive Streamlit interface.
```powershell
streamlit run app.py
```

### Step 6: Final Evaluation & Recall Check
Analyze how many injected thefts were successfully caught and check for false positives.
```powershell
python evaluate.py
```

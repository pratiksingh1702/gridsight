The problem

Technical gaps in grid visibility and loss detection

Smart meters generate data every 15 minutes, but this high-resolution data is often underutilized for operational intelligence.

Blind Spot A

No early warning for demand spikes

Distribution transformers and feeders have hard capacity limits. When demand unexpectedly peaks — on a 40°C afternoon or during a major event — transformers trip, cables overheat, and outages ripple across entire neighbourhoods. Control rooms currently react after the fact. There is no mechanism to look 1–24 hours ahead.

Blind Spot B

Revenue leakage through theft & tampering

Many losses are deliberate — meter bypass wiring, magnet-based meter slowing, firmware manipulation, or direct tapping from the LT line. Today, inspections are random and yield is low. There is no evidence-based system to target investigations where the probability of finding tampering is highest.

How it works

A read-only intelligence layer. No modification to existing systems.

GridSight ingests data via one-way file drops or read-only API feeds. It never writes back to any BESCOM system. All outputs are advisories — every action requires a human decision.

01

Data ingestion & validation

Smart meter CSVs arrive on a 15-minute or hourly schedule. The pipeline validates timestamps, cleans data quality issues, and imputes short gaps using the peer-group median for that time slot. Offline meters are flagged immediately on the dashboard.

TimescaleDBPython · PandasGreat Expectations
02

Per-meter demand baseline (Prophet)

Facebook Prophet builds a unique baseline for each meter — learning daily and weekly consumption patterns, Bangalore-specific holiday effects, and weather sensitivity via a temperature co-variate. Fast to train; interpretable by design.

Facebook ProphetWeather API (area-level)
03

Zone-level forecasting & risk classification

Per-meter forecasts are aggregated to feeder and transformer level, then refined by a Temporal Fusion Transformer that produces probabilistic P10/P50/P90 bands. Each transformer gets a colour-coded risk zone — GREEN through RED — updated every hour.

PyTorch TFTP10 / P50 / P90 bands
04

Five-agent anomaly detection

Five independent specialist agents run in parallel on every meter. A meter is only escalated when at least 3 of 5 agents independently raise an alarm and the flag has persisted for 7+ days. No single signal ever triggers an inspection.

What was observed

Sustained 38% consumption drop

From 12-Apr-2026, daily kWh dropped from a 14-day average of 18.4 kWh to 11.3 kWh. Peer group of 17 similar meters shows no concurrent drop. Pattern shows near-zero readings between 23:00–05:00 while daytime usage continues normally — consistent with a bypass wire active at night.

Detection agents

Five independent signals. Conviction requires consensus.

No single signal ever triggers an inspection. A meter is escalated only when at least 3 of 5 agents raise alarms simultaneously, the composite score exceeds 75/100, and the flag has persisted for 7+ days.

Agent 01

Break detector

Watches each meter's own history for a sudden, sustained downward break — the signature of a bypass wire being installed. Ignores random noise; detects sustained shifts.

CUSUM change-point analysis
Agent 02

Peer comparator

Groups each meter with 15–20 "social twins" — same type, same sub-area, similar usage profiles. A consumption far below the peer band stands out even when seasonal effects shift everyone.

K-Nearest Neighbours
Agent 03

Impossibility checker

Catches readings that defy physics or known occupancy patterns — near-zero consumption at a permanently occupied premise, readings below standby minimums, wrong tariff patterns.

Rule engine
Agent 04

Pattern matcher

Scans for known fraud fingerprints: perfectly flat lines (firmware manipulation), night-zero day-normal patterns (bypass active at night), periodic dips at meter-reading intervals.

Template signature matching
Agent 05

Feeder balance auditor

Compares total energy fed into a transformer against the sum of all consumer meters on that feeder. A persistent gap above 5–8% signals that one or more meters are under-reporting.

Mass balance / NTL detection
Fusion

Score fusion & escalation gate

Scores fused by weighted sum, weights updated by field feedback. Escalation requires: 3/5 agents firing + composite score >75 + 7-day persistence. Human sign-off before any field visit.

Weighted ensemble
Risks & mitigation

We know where the system can fail. Here is how we handle it.

Every AI system has failure modes. GridSight is designed with explicit mitigations — and human sign-off before any action is ever taken.

⚠
Risk — false positives

Flagging innocent meters

A 3-of-5 agent consensus gate + 7-day persistence + composite score >75/100 ensures no single anomaly triggers an investigation. Estimated false positive rate <10%. All FP are visible on the dashboard with full audit trail, and field feedback re-weights agent scores over time.

⚡
Risk — data quality

Gaps, noise & offline meters

Great Expectations validates every batch before any model sees data. Short gaps (<2 hrs) are imputed using peer-group median for that slot. Meters offline >2 hours are flagged on the dashboard immediately — never silently treated as zero consumption.

🔒
Risk — data privacy

Sensitive consumption data

No raw meter data leaves BESCOM's compute perimeter. All models run fully on-premise. No hosted LLM is used at any stage of the pipeline. Outputs are aggregated scores and flags — raw readings never appear in any external system.

Non-negotiable: Zero hosted LLM on sensitive data
All models (Prophet, TFT, scikit-learn agents) run inside BESCOM's compute environment. No data leaves the perimeter at any stage.
